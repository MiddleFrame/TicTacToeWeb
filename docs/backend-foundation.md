# Backend foundation: ограничения и админка

Обновлено 3 сентября 2026 года. Бюджет: бесплатные сервисы либо собственный маломощный сервер. В этом изменении нет новых подписок, Redis, платного rate-limit API или дополнительной базы. Текущее размещение остаётся в Sites с D1; перенос на свой сервер ещё не реализован.

## Защита API

Проверка находится в `worker/index.ts` до обработчиков `/api/`, поэтому распространяется и на веб, и на запросы Android к этому backend. Статика и CORS OPTIONS счётчик не расходуют.

| Категория | Лимит на адрес / IPv6-подсеть |
| --- | --- |
| Создание гостя | 10 за 10 минут |
| Подключение Google | 15 за 10 минут |
| Чтение API | 240 в минуту |
| Изменения API | 90 в минуту |
| Админка | 60 в минуту |

Окна фиксированные: около границы двух окон возможны два последовательных разрешённых пакета запросов. Это защита от частого повторения, не точный скользящий счётчик и не защита от DDoS. Игроки за одним NAT разделяют лимит: при появлении реальной аудитории пороги необходимо проверить по нагрузке, прежде чем повышать.

- Источник адреса — `CF-Connecting-IP`, устанавливаемый доверенным Cloudflare-прокси. Адаптер Worker явно доверяет этому edge-заголовку: прокси Sites не сохраняет `request.cf`, поэтому наличия этих метаданных недостаточно для определения адреса. Обычные `X-Forwarded-For`, email и cookie для обхода лимита не используются. IPv6 нормализуется до /64. См. [правила Cloudflare для этого заголовка](https://developers.cloudflare.com/fundamentals/reference/http-headers/#cf-connecting-ip).
- Если доверенного адреса нет, применяется общий резервный счётчик, а не отключение защиты. При переносе на свой сервер потребуется отдельный доверенный адаптер IP от соединения или своего reverse proxy. Нельзя просто доверять присланному клиентом заголовку.
- В базе сохраняется SHA-256 ключа, а не открытый IP. Это псевдонимизация, не обещание анонимности. Старые счётчики очищаются порциями до 128 строк после каждых 128 разрешённых запросов в процессе, если окно истекло более суток назад. При отсутствии трафика очистка не запускается.
- Инкремент и проверка лимита выполняются одним атомарным SQL UPSERT. Отдельные процессы Worker используют одну базу, а не независимые разрешающие кеши.
- Ответ при превышении: `429`, `Retry-After`, JSON `rate-limited`. Только отказы кешируются в памяти, максимум 2048 ключей на процесс.
- При ошибке базы: `503` и `Retry-After: 30`; операций без проверки нет. В существующем клиенте сетевая ошибка отображается обычным механизмом ошибки; автоматический бесконечный retry не добавлялся.
- Защита сама расходует квоты: разрешённое обращение добавляет один запрос счётчика, записи и обслуживание индексов. Нет платного обхода исчерпанной квоты. См. [учёт D1](https://developers.cloudflare.com/d1/platform/pricing/).

## Админка

Открыть `/admin`. Первая версия только для чтения:

- Google-вход в браузере через существующий сервер проверки подписанного токена, nonce и сессии;
- разрешённые Google-email задаются в серверной `ADMIN_GOOGLE_EMAILS` через запятую; пустая строка закрывает доступ всем;
- email берётся из подтверждённой серверной Google-привязки, не из параметров запроса; на каждом обращении проверяется активный статус аккаунта;
- поиск по точному нику, публичному коду или ID, не более 20 результатов;
- просмотр кошелька, до 200 предметов, последних 50 операций валюты и 20 записей аудита;
- просмотр создаёт запись с ID администратора и целевого аккаунта. Нет фонового опроса, экспорта всех игроков, редактирования валюты, компенсаций или банов;
- данные отдаются с `Cache-Control: no-store`, без CORS-доступа к административным данным, страница помечена `noindex`. Скрытая кнопка или URL не считаются защитой.

Первый вход требует настроенного `GOOGLE_AUTH_CLIENT_ID` и разрешённого JavaScript origin сайта в Google Cloud OAuth. Используется стандартная кнопка Google, скрипт загружается только после нажатия «Войти через Google». После успешного входа права снова проверяет backend. OAuth client ID публичен по назначению; allowlist остаётся серверным.

Если Google выдаёт `origin_mismatch`, добавить точный origin сайта в **Google Auth Platform → Clients → Web client → Authorized JavaScript origins**. Не отключать проверку токенов и не выдавать доступ по email, введённому в поле. Смена Google-аккаунта переключает на уже существующий игровой профиль по прежним правилам привязки, не объединяет валюту двух профилей.

Проверка владельца после публикации: войти разрешённым Google-аккаунтом; найти свой публичный код; сравнить валюту и коллекцию с игрой; открыть карточку и увидеть запись аудита; выйти и убедиться, что данные больше не открываются. Тестирование Google-входа требует участия владельца: его пароль или токен вручную не запрашиваем.

## Проверки разработки

- Автотесты выполняют настоящие SQL-запросы в SQLite со всеми миграциями: одновременные лимиты, сброс окна, ограниченная очистка, индексы поиска, SQL injection, лимиты истории и аудит без изменения валюты.
- Проверка HTTP локально: страница, запрет неавторизованному клиенту, ответы 429 с Retry-After, CORS для Android.
- Миграции только добавляют `api_rate_limits` и `admin_audit_log`, существующие таблицы и прогресс не пересоздаются.
- После изменений запускаются тесты, lint и production build.
- Повторяемая HTTP-проверка: локально применить миграции (`pnpm db:local:migrate`), задать только для теста `ADMIN_GOOGLE_EMAILS=admin-check@example.test` в игнорируемом `.dev.vars`, запустить `pnpm dev --port 3193`, затем `node tests/backend-http-check.mjs`. Скрипт создаёт временные аккаунты исключительно в локальной SQLite и удаляет только свои фикстуры. После проверки убрать тестовый `.dev.vars` и остановить сервер. Никогда не настраивать этот тестовый адрес администратором опубликованного сайта.
- Дополнительный `tsc --noEmit --incremental false --allowImportingTsExtensions` выявил три ранее существовавшие ошибки в `useMatchmakingAnimation.ts`, `useScenePattern.ts` и `card-interaction.ts`; они остаются отдельной задачей. Обычный production build и lint проходят.
- Эти изменения серверные и административные, не требуют нового Android AAB. Android Studio остаётся отдельным инструментом проверки мобильного release; новый APK на телефон не ставится.
