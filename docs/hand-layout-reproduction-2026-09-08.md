# Растягивание поля при заполнении руки: воспроизведение на Android 50

**Проверка 2026-09-09:** владелец установил окончательную 51 из Play; сценарии с пятью картами, возвратом/розыгрышем карты и закреплением магазина прошли на том же телефоне. Подробности в дополнении ниже. Ограничения проверки 2026-09-08 сохранены как история.

Дата: 2026-09-08. До правки: source HEAD `21be24ca4814e2e1f9ad3e1422a750622272ed1d`; установленная из Play игра — **versionCode 50 / 0.7.9**. Источник CSS 50 — `2c1a9af8cff7538a92ae79a41584cdc85981eab5`. GameScene, GameHud и engine между этими commits не менялись. Владелец разрешил управление телефоном; игра не переустанавливалась, данные не очищались.

## Что воспроизведено

После включения владельцем отдельной настройки безопасности USB ADB-касания заработали. На телефоне `23013PC75G`, Android 15 / API 35, WebView `com.google.android.webview 151.0.7922.199` выполнен сценарий:

1. Открыть установленную игру 50 и нажать «Игра с ботом». В руке две карты, поле и «Конец хода» помещаются в экран.
2. Один раз нажать «Конец хода» и подождать бота около пяти секунд. В руке четыре карты.
3. Ещё раз нажать «Конец хода» и подождать бота. В руке пять карт; поле и обе полосы здоровья растягиваются вправо, «Конец хода» частично скрывается за правым краем. Системные значки и кнопка паузы остаются на прежних местах.

**Это воспроизведение на настоящей версии 50, а не проверка новой сборки.** Серия быстрых касаний не нужна. ADB подтвердил `versionCode=50` до запуска. Тестовые снимки сохранены локально в ignored `work/zoom-repro-50-2026-09-08/botinitial.png`, `botfour.png`, `botfive.png`; в Git они не публикуются. На телефоне использовалось разрешение снимка 1080 × 2400 при override density 420.

## Причина и ущерб

- **P1 / малая трудоёмкость:** неявный столбец CSS grid в `app/globals.css:4374` зависел от минимальной ширины содержимого. Пять flex-слотов шириной 102 px с отступами −4 px требовали 470 px. На узком экране эта ширина растягивала всю сетку, включая поле и управление; родитель с `overflow: hidden` обрезал правую часть. Пользователь терял доступ к кнопке и части поля.
- Добор двух карт и предел руки пять — штатные правила `app/game/engine.ts:22`, `app/game/engine.ts:637`. Они не изменены. Повторные пропуски просто доводят руку до её максимального размера.
- На браузерном стенде с исходным CSS 50 `visualViewport.scale` оставался **1** до и после воспроизведения. Ширина поля менялась от состава руки. Это прямое измерение CSS-механизма; масштаб установленного release-WebView не выдаётся за измеренный через DOM.
- Прежние `setSupportZoom(false)` и `touch-action: manipulation` из первой сборки 51 не устраняют эту причину. [Предыдущий отчёт](mobile-ui-fixes-2026-09-08.md) сохранён как история первоначальной гипотезы и проверки магазина.

## Исправление

В `app/globals.css:4385` задан явный столбец `minmax(0, 1fr)`, ограниченный доступной шириной. В `app/globals.css:4671`–`4696` рука получила рассчитанный шаг веера: при нехватке места карты перекрываются, не увеличивая размер родительской сетки. Существующие `--fan-index` / `--fan-center` из `app/components/game/GameHud.tsx:147` определяют положение; новая React state или обработчики не добавлены.

Размеры слота и карты используют одинаковые CSS-переменные, включая существующий компактный режим при высоте до 700 px (`app/globals.css:5214`). Координаты перетаскивания по-прежнему берутся из фактического `getBoundingClientRect()` кнопки. Это не самостоятельное доказательство прохождения реального drag/release; такой сценарий нужно проверить в обновлённой установленной игре.

Механика, экономика, сохранения, подпись, SDK/profile и публичные API не меняются. Исправление sticky-панели магазина из первоначальной 51 сохранено. По просьбе владельца номер **51 переиспользуется**, поскольку первоначальный файл ещё не загружался в Google Play; временная сборка 52 не предназначена для загрузки.
