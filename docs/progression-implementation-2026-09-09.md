# Внедрение кривой XP и пустых уровней

9 сентября 2026. Объём: XP, шкалы прогресса и временно пустые дорожки. Это не внедрение всей коммерческой экономики.

## Изменения

| Правило | Раньше | Теперь |
| --- | --- | --- |
| Цена очередного уровня L стихии | 1000 XP | `250 + 20 × (L−1)` |
| Цена очередного уровня L основы | 1000 XP | `550 + 45 × (L−1)` |
| Всего до уровня 100 | 100 000 XP | 124 000 стихии / 277 750 основы |
| XP повторки | 100 | 30 |
| XP новой карты | 0 | 0, без изменения |
| XP раунда на экземпляр карты | 3/1/0 победа/поражение/ничья | Без изменения; начисляется в коллекцию карты |
| Новые награды уровней | 10/25 монет free/premium | Пусто, без выдачи и кнопки получения |

Косметические вехи premium 40/60/80/100 сохранены как подписи «Добавим позже»: открытие карт, внешний вид карты, постановка, анимация на поле. Косметическое имущество пока не создаётся. Исторические причитающиеся монеты вынесены отдельно в «Награды до обновления», не заменяют косметические вехи.

UI, локальная прогрессия и backend используют одну чистую политику [progression-curve.ts](../app/game/progression-curve.ts). Шкалы показывают XP внутри текущего уровня и его фактическую цену, а не старый делитель 1000.

## Переход сохранений и очереди

- Формат pass получает `version: 2` и необязательный `legacyXp`. Отсутствующая версия считается v1; неизвестная будущая версия отклоняется без очистки сохранения. SQL-схема не меняется: обновляется JSON существующей записи.
- Для старого XP `x`: `k = floor(x/1000)`, `r = x mod 1000`; новая величина `F(x) = threshold(k) + floor(r × cost(k+1)/1000)`. На старом максимуме берётся новый максимальный порог. Достигнутый уровень, premium и ключи полученных наград сохраняются; потеря дробной доли меньше одного нового XP. Повторное чтение v2 не пересчитывает её снова.
- Старые команды в очереди не получают новую версию задним числом. Сохраняются operation ID, порядок и квитанции. Для команды v1 используется старая повторка 100 и прибавляется `F(legacyXp + delta) − F(legacyXp)`; для v2 — новые сырые XP. Это предотвращает повторную конвертацию уже начисленных офлайн-операций.
- Чтение сервера только проецирует старый JSON. Миграция записывается вместе со следующей успешной мутацией, ledger и квитанцией в существующей атомарной транзакции с проверкой ревизии. Ошибка откатывает весь пакет; повтор не выдаёт награду заново.
- Старые квитанции не переписываются и не истекают. Новый клиент отправляет версию команды и заголовок `X-TTTP-Progression: 2`. Необновлённый клиент получает старую шкалу в ответе; все уровни выше его подтверждённой legacy-границы помечаются недоступными для получения **только в ответе**, не в сохранении. Это не даёт старому офлайн-интерфейсу обещать монеты за новые пустые уровни. После синхронизации заработанное по старым правилам снова доступно.
- Старые ещё не забранные монеты доступны без повторной выдачи полученных. Новые команды v2 не создают таких наград. На L100 начисление ограничивается порогом; показ XP повторки учитывает фактически поместившийся остаток.

### Восстановление и ограничения совместимости

Безопасный откат — исправление вперёд с сохранением поддержки v1/v2, `legacyXp`, очередей и квитанций. Нельзя просто вернуть прежний сервер: его предел 100 000 обрежет новый XP. Нельзя удалять очередь, повторно конвертировать v2 или массово восстанавливать старый снимок поверх более новых транзакций. При повреждении сначала остановить затронутые записи, отдельно сохранить их и квитанции разрешённым операторским способом, затем применить проверенный адресный repair с контролем ревизии; в этой задаче реальные данные игроков не читались и массовая миграция не запускалась.

Переходная поддержка v1 предназначена для существующего прототипа. Версия, присланная клиентом, **не доказывает право** на старые награды. До ценной общей экономики нужны серверная проверка игровых результатов и явное завершение перехода старых клиентов; один этот патч не делает ranked или покупки защищёнными от поддельных команд. Старый клиент может временно иначе предсказывать смешанный офлайн-прогресс до ответа сервера; авторитетное состояние и очередь не подменяются его экранной шкалой.

## Проверки

- `pnpm run quality`: архитектура, TypeScript, **245/245 тестов**, lint, web production build, Android web build и бюджет. Native Android/AAB, подпись и Google Play не затрагивались.
- Новые исполняемые тесты: все 100 порогов обеих коллекций; сохранение уровня и части XP; локальное восстановление; SQLite rollback, повтор, конкуренция старой/новой команды; старая очередь round → claim → purchase с потерянным подтверждением; неизменность исторической квитанции; будущие версии; пустые награды.
- Реальный React SSR на русском/английском: 200 пустых ячеек, четыре косметические подписи, правильные шкалы и отдельные старые награды. Старый DTO проверен и на переходе через следующий уровень офлайн, а не только на уже достигнутом уровне.
- Локальный preview возвращает HTTP 200. Интерактивная проверка браузером и измерения на Android-устройстве не выполнялись; SSR не выдаётся за визуальное или аппаратное тестирование.
- Android web assets: **1 171 626 → 1 173 762 байта** при лимите 1 500 000; initial JS **323 068 → 325 397** при лимите 340 000. Это размер артефактов, не доказательство FPS/CPU/батареи. Политика бюджетов не расширялась.
- Вспомогательный `build-site.mjs` Sites не смог запустить `npm` из-за Windows-кавычек. Использован успешно завершившийся тот же `vinext build` из `quality`; зависимости, vendor-скрипты и конфигурация сборки ради обхода не менялись.

## Что осталось отдельно

Монеты **7 за дневную рекламу / 1 за победу / 3 за карту**, цены пачек, стартовый кошелёк, IAP, прямая покупка XP полной коллекции и настоящие награды дорожек здесь не внедрены. Текущие заглушки магазина и рекламы не менялись. Поэтому расчёт **370/728 дней** для будущей экономики нельзя заявлять как уже достигнутый темп работающей игры. GAME_DESIGN.md и ранее незавершённые правки других аудитов не переписывались этой реализацией.
