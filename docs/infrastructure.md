# Размещение, база данных и доступ

Зафиксировано 3 сентября 2026 года. Этот документ описывает фактическое размещение проекта, а не предполагаемый личный тариф Cloudflare владельца.

## Кто создал базу и кто ею управляет

- Постоянная база игры — Cloudflare D1, управляемая платформой Sites. Sites создаёт реальные ресурсы Cloudflare и подключает их к серверной части проекта.
- Для создания этой базы не выполнялись регистрация личного Cloudflare-аккаунта владельца или вход в него. Отдельная регистрация в Cloudflare для текущего размещения не понадобилась.
- Доступ к проекту предоставлен через уже подключённый Sites. Владение проектом Sites не означает прямой доступ к аккаунту Cloudflare инфраструктурного оператора.
- База не появится автоматически в личном кабинете Cloudflare, если владелец зарегистрирует там новый аккаунт.
- Google-аккаунт для входа в игру и админку, Google Cloud OAuth и Play Console не являются Cloudflare-аккаунтом и не управляют этой D1.
- Корректное название текущей конфигурации: **Cloudflare D1 через Sites**. Называть её «наша база D1 Free» без подтверждения тарифа нельзя.

## Как подключено в проекте

- Сайт и API: <https://tic-tac-toe-plus-alpha.stofs.chatgpt.site>.
- Существующий Sites project ID: `appgprj_6a69af78ebc88191b3a65519337199c1`. Источник истины — [`.openai/hosting.json`](../.openai/hosting.json); не создавать новый Site для обычного обновления.
- В том же файле `d1: "DB"` обозначает логическую привязку, а не идентификатор физической базы или тариф. `r2: null`: отдельное R2-хранилище проектом не запрошено.
- Worker получает D1 через `env.DB`; доступ изолирован в [`db/index.ts`](../db/index.ts). Схема — [`db/schema.ts`](../db/schema.ts), последовательные миграции — `drizzle/`.
- Клиенты обращаются к серверному API, а не непосредственно к D1. Android использует настроенный `NEXT_PUBLIC_API_ORIGIN`; веб-клиент — API своего origin.
- Данные рабочей базы находятся в облаке, не внутри Android-билда и не на компьютере владельца. Выключение компьютера их не затрагивает. Обычное обновление существующего Site не очищает базу.
- Локальная SQLite для разработки находится под `.wrangler/state/v3/d1/`. Это отдельная база, не резервная копия production и не автоматическая реплика. Каталог `.wrangler/` игнорируется Git.

## Что хранится

После реализации удаления аккаунтов в production проверены 12 таблиц: `users`, `identities`, `sessions`, `profiles`, `wallets`, `inventory`, `player_progress`, `store_purchases`, `reward_ledger`, `api_rate_limits`, `admin_audit_log`, `account_deletion_tickets`.

Это аккаунты, подтверждённые Google-привязки/email, хеши сессий, профили, валюта, карты и колода, операции экономики, счётчики защиты, административный аудит и временные подтверждения удаления. Пароли Google игра не получает. Картинки, музыка и файлы Android-билда в D1 не складываются; история матчей и ranked ещё не реализованы.

Игровой локальный снимок и рабочая облачная база — разные слои. Android сохраняет в снимке одиночный прогресс и очередь неподтверждённых операций, поэтому недоступность Cloudflare не блокирует магазин, колоды, бота и roguelike. Удаление данных приложения уничтожает несинхронизированную очередь, но не удаляет облачный аккаунт. Серверное удаление и ограничения для офлайн-копий описаны в [account-deletion.md](account-deletion.md).

## Подтверждённые и неизвестные ограничения

Фактический тариф оператора, выделенные этому проекту квоты, текущий расход места/операций, физический регион и условия резервного копирования **не подтверждены доступными настройками Sites**. Нельзя обещать конкретную страну хранения, безлимитное использование, бесплатность навсегда, определённое число игроков или 7-дневное восстановление именно нашей базы.

Для сравнения, справочные значения обычного Cloudflare D1 на Workers Free, проверенные 3 сентября 2026 года:

| Показатель | Обычный D1 Free, не подтверждённая квота Sites |
| --- | --- |
| Размер одной базы | 500 МБ |
| Суммарное хранилище аккаунта | 5 ГБ |
| Прочитанные строки | 5 млн в сутки |
| Записанные строки | 100 тыс. в сутки |

Источники: [D1 limits](https://developers.cloudflare.com/d1/platform/limits/), [D1 pricing и учёт строк](https://developers.cloudflare.com/d1/platform/pricing/). При планировании собственного размещения проверить актуальные условия повторно.

Считаются строки, а не игроки или действия интерфейса. Один запрос может прочитать множество строк; обновление индексов тоже расходует записи. Защита API и аудит дополнительно обращаются к базе. У обычного Free исчерпание суточных квот приводит к ошибкам до сброса квоты; это не автоматический переход на платный тариф. Ограничения Worker и других сервисов учитываются отдельно.

Проектное бюджетное правило остаётся прежним: бесплатные сервисы либо уже доступный собственный маломощный backend. Новые платные тарифы и услуги — только по отдельному согласованию владельца.

## Доступ и безопасность эксплуатации

- Просмотр игроков — через закрытую `/admin`; это не полный административный доступ к инфраструктуре и не инструмент резервного копирования.
- Инструменты Sites позволяют проверить привязки и таблицы рабочей базы. Настройки доступа к Site и серверные переменные управляются через Sites.
- Секреты, дампы с данными игроков, реальные токены сессий и учётные данные инфраструктуры не коммитить. Android-ключ и параметры подписи остаются в игнорируемом `android-config/private`.
- SQL-миграции и Git хранят структуру базы и код, **не содержимое production**. Копия репозитория сама по себе не позволяет восстановить данные игроков.
- Не удалять и не пересоздавать Site/базу для проверки, не переписывать применённые миграции. До миграции данных или восстановления нужен проверенный экспорт и понятный план отката.

## Если понадобится личный Cloudflare или свой сервер

Это отдельный перенос, пока не реализованный. Для личного Cloudflare понадобятся аккаунт владельца и явно предоставленный доступ; новая база и Worker не унаследуют данные Sites автоматически. Для собственного сервера потребуется совместимый серверный адаптер, а не просто копирование текущего Worker. Клиентская очередь и локальные редьюсеры не зависят от D1; при сохранении HTTP-контрактов достаточно переключить Android API origin, а при другом протоколе заменить транспорт в `app/game/player-progress-client.ts`.

Порядок: согласовать место и бюджет → выяснить поддерживаемый способ экспорта данных из Sites → проверить сохранность и восстановление копии → перенести схему и данные → настроить переменные и Google OAuth origins → проверить авторизацию, экономику и удаление → переключить API клиентов. Нельзя считать экспорт, перенос или резервное восстановление уже настроенными.

## Ближайшие задачи инфраструктуры

- [ ] Уточнить реальные квоты Sites, область их действия и реакцию на превышение.
- [ ] Узнать доступный способ наблюдать размер базы, чтения и записи; затем добавить ограниченный учёт без частого polling.
- [ ] Уточнить регион, сроки хранения резервных копий и процедуру удаления данных из них.
- [ ] Проверить экспорт и восстановление на отдельной тестовой базе, не на данных владельца.
- [ ] Подготовить порядок восстановления с учётом запросов удаления; старый backup не должен возвращать удалённые аккаунты.

Эти задачи не закрыты самим фактом успешной публикации сайта или наличия таблиц D1.
