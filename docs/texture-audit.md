# Аудит изображений Tic Tac Toe Plus

Дата: 3 сентября 2026. Проверена текущая самостоятельная веб-версия проекта и её Android-ресурсы. Это проверка файлов, прозрачности, ссылок в исходниках и способов отображения. Время загрузки, FPS и фактическая GPU-память в браузере не измерялись. Изображения и код игры не изменены.

**Основной результат**

В игровой веб-графике нет огромных одноцветных квадратов, растровых заливок кнопок или больших текстур рамок. Простые поверхности, обводки и скругления уже реализованы средствами CSS.

Для 33 игровых PNG оценка одного полного RGBA-декодирования каждого изображения составляет 2,85 МиБ: сумма ширина × высота × 4. Это не измерение памяти вкладки: браузер может декодировать не всё сразу, создавать дополнительные поверхности или освобождать изображения. Сжатый размер PNG и память после декодирования — разные величины.

В public не обнаружено одинаковых растров ни по байтам, ни по декодированным RGBA-пикселям. У всех 34 растров public найдены ссылки в исходниках. Файл, лежащий в public, доступен для выдачи, но не обязательно загружается при каждом открытии игры.

Обрезать прозрачность у карт без изменения способа отображения нельзя: background-size: contain масштабирует весь исходный холст. После обрезки рисунок станет крупнее или сдвинется. Нужны общий логический размер, координаты рисунка и отступы в данных либо сохранённый SVG viewBox. У ice-encirclement-o и place-more-o холсты уже меньше, чем у соответствующих X-вариантов; при переработке надо проверить согласованность масштаба.

**Правила для подготовки графики под веб**

1. Одноцветная заливка — background-color. Отдельный белый PNG не нужен даже размером 1×1. Простая рамка — border, скругление — border-radius, обычный градиент — CSS gradient.
2. Художественная растягиваемая рамка — небольшой 9-slice-скин через border-image. Углы сохраняются, полосы между ними растягиваются или повторяются. Рисунок центральной области можно включить через fill; одноцветную середину удобнее задать фоном. Скругление рамки нужно предусмотреть в самом скине: border-radius не скругляет border-image. [Справка MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/border-image).
3. Простые значки и контурные рисунки — SVG. Для inline SVG можно использовать currentColor, для внешнего одноцветного силуэта — CSS mask с цветным фоном. Обычный внешний SVG в img не наследует currentColor со страницы автоматически. Разные цветовые темы не требуют отдельных растровых экспортов.
4. Для растра ориентироваться на максимальный размер в интерфейсе, включая увеличение, и плотность экрана. Например, рисунок 190 CSS px для DPR 2 требует порядка 380 пикселей по ширине для отображения без увеличения исходника. Не увеличивать существующий PNG искусственно: это не добавляет деталей. [О плотности пикселей — MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio).
5. Формат выбирать по рисунку. Для графики с чёткими краями и прозрачностью сравнивать PNG и lossless WebP; для сложных иллюстраций — WebP/AVIF с подходящим качеством. SVG полезен для геометрии, но не для встроенной внутрь растровой картинки. AVIF не вводить без проверки поддержки или fallback: проект допускает Android WebView от версии 60. [Форматы изображений — MDN](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Image_types).
6. Проверять альфа-канал и пустые поля, сохраняя ожидаемые координаты и размер рисунка. Проверять экспорт на светлом и тёмном фоне: белая кайма вокруг прозрачности может проявиться только на одном из них.
7. Повторяемая фактура — бесшовный маленький тайл и background-repeat. Для растяжения подходит однородная область; узнаваемый повторяющийся орнамент лучше повторять, чтобы не деформировать.
8. Для обычных img, SVG и CSS-background не нужно автоматически округлять размеры до степеней двойки. Атлас также не является обязательной оптимизацией DOM-интерфейса: он связывает загрузку разных картинок, усложняет замену файлов и может заставить декодировать лишнюю большую поверхность. Решение для WebGL требует отдельной оценки.
9. Исходники высокого разрешения и варианты дизайна хранить отдельно от runtime-папки. В public/game оставлять только нужные экспортированные версии. Общие изображения подключать по одному URL.
10. Для будущих больших иллюстраций предусмотреть srcset/sizes или image-set, загрузку внеэкранных изображений по требованию и версионирование ресурсов для кэша. Главную сразу видимую картинку не откладывать lazy-loading. Эти меры стоит выбирать по измерениям загрузки. [Производительность изображений — web.dev](https://web.dev/learn/performance/image-performance).

Пример настройки 9-slice: условная рамка 48×48 с угловыми областями 12×12. Число 12 в slice означает отступ линии разреза в исходном растре; ширина отображаемой рамки задаётся отдельно.

```css
.ornate-panel {
  border: 12px solid transparent;
  border-image-source: url("/game/ui/panel-frame.png");
  border-image-slice: 12;
  border-image-width: 12px;
  border-image-repeat: stretch;
  background: var(--paper);
}
```

panel-frame.png здесь — пример имени будущего скина, такого файла в проекте нет.

**Что учесть в текущей архитектуре**

Компонент app/components/game/Image.tsx — оболочка над обычным img. Он не меняет размеры файлов и не создаёт WebP или srcset автоматически. Рисунки карт часто подключены через CSS background-image. Уменьшение элемента стилями не уменьшает загружаемый файл.

build/android-public-assets-plugin.ts копирует public/game целиком. Любой будущий забытый экспорт в этой папке увеличит Android-пакет, даже если экран на него не ссылается. Текущий набор маленький, но проверка списка копируемых файлов будет полезна при росте коллекций.

При жалобах на плавность отдельно измерить большие blur, backdrop-filter, тени и анимации. Небольшой размер PNG сам по себе не гарантирует дешёвый кадр, а сложные CSS-эффекты не становятся бесплатными от отказа от растров. В рамках этого аудита замеров кадров не было.

Приоритет следующей реализации: единые векторные примитивы и фоновый тайл; согласование экспорта карт и размеров просмотра; эксперимент со сжатием ice.png; проверка состава runtime-ресурсов в сборке. Массовое уменьшение PNG и упаковка всего в атлас по текущим данным не обоснованы.
