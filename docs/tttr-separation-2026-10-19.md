# Разделение ТТТП и ТТТР

Дата: 19 октября 2026 года. Исходный commit: `58433cc3c1784005680f2d95cfa1b9fead8f4aed`.

## Принятое ограничение этапа

Владелец запросил две игры внутри одного приложения: ТТТП и ТТТР, с отдельными меню, прогрессией, картами, экономикой и магазином, двусторонним переходом и выбором стартовой игры. В уточнении выбраны полностью новые карты и эффекты ТТТР, но их проектирование, валюта и покупки отложены: сначала разделить игры, наполнение позже. Этот этап не вводит новые цены, награды, платёжные продукты или эффекты.

## Изменённое поведение

- В меню ТТТП больше нет запуска рогалика как обычного режима. Есть переход в самостоятельное меню ТТТР и кнопка выбора текущей игры для запуска по умолчанию. В ТТТР есть обратный переход и такая же настройка.
- При первом запуске без настройки открывается ТТТП. Выбор записывается отдельно, в `tttp-default-world-v1`, только по нажатию соответствующей кнопки; простое переключение его не меняет.
- Обе игры загружаются через динамический import. Запрос модуля и загрузочная анимация выполняются одновременно. Это асинхронная загрузка в браузере, без отдельного системного процесса или Worker. Отменённый/устаревший import не меняет текущую игру; ошибки имеют повтор и возврат. Ошибки отрисовки обрабатывает существующая граница ошибок.
- Одновременно смонтирован один игровой раздел; на время перехода предыдущий интерфейс недоступен для ввода. При отмене он остаётся на месте. После успешного перехода подписки боя и Photon освобождаются существующими владельцами lifecycle. Общие звук, активность приложения, коллекция и барьер аккаунта живут в `GameSessionProvider` над сценами; незавершённые операции аккаунта переживают смену игры.
- Общий `GameRuntime` сохраняет единственную реализацию боя. `PlusWorld` получает прежнюю коллекцию и начисление опыта через порт постоянной сессии приложения. `RogueliteWorld` использует общий звук и активность, не создаёт коллекцию ТТТП и не вызывает её команд прогрессии. Фоновая синхронизация уже накопленных операций ТТТП продолжает работать на уровне приложения.
- В ТТТР сохраняются начатые забеги, суммарные победы на этапах и лучший результат. Результат записывается при продолжении после боя либо при выходе из результата в меню. Повторная обработка того же этапа не удваивает статистику; при ошибке записи переход не подтверждается.
- Переход между играми доступен из их меню. Возвращение из незавершённого забега завершает текущую попытку; новый забег начинается с первого этапа. Возобновление боя после перезапуска не добавлено.
- Карты и магазин ТТТР имеют собственные разделы с явным сообщением о следующем этапе. Нынешние бои используют прежний прототипный набор, независимо от владения картами ТТТП. Новые карты, эффекты, валюта и покупки в этом изменении не реализованы по уточнению владельца.
- Язык и звук остаются общими настройками приложения.

## Сохранения и совместимость

Формат и ключи ТТТП, его облачная схема, балансы, ownership, пути, очереди и квитанции не меняются. Уже полученный опыт не вычитается. Backend сохраняет прежнюю обработку `record-round: roguelike`, чтобы завершить синхронизацию старых offline-очередей; новый клиент больше не создаёт таких команд. Это совместимость старого solo-прототипа, не серверное подтверждение результатов новых забегов.

Новая статистика ТТТР — отдельный локальный снимок `tttr-progress-v1` с `version: 1`; существующие данные ТТТП в него не копируются. Это профиль игры на устройстве, без Google/облачной синхронизации и привязки к аккаунту ТТТП. Смена аккаунта ТТТП не переносит в него эту статистику. Нет реальной валюты, ledger или экономических квитанций ТТТР. Перед введением экономики и аккаунтов потребуется отдельная схема владения и миграция.

Отсутствующий снимок создаётся с нуля. Повреждённый или неизвестный будущий формат не перезаписывается: показана ошибка, запуск забега блокируется до успешного чтения. Каждая запись снимка использует один `localStorage.setItem` до отображения успеха; многоключевая транзакция не заявляется. Активный run ID и порядковый номер этапа защищают от повторов и устаревшего результата; после старта следующего забега команды предыдущего run ID отклоняются. Очереди повторов между забегами нет. Несколько вкладок не являются согласованной серверной сессией.

Откат: вернуть исходники на предыдущую версию, не удаляя `tttr-progress-v1` и `tttp-default-world-v1`. Старый клиент их не читает, сохранения ТТТП доступны в прежнем формате. Для восстановления ТТТР вернуть эту версию клиента. Production SQL и данные игроков не изменялись.

## Проверки и измерения

- До изменения: `pnpm test`, 245/245.
- После изменения: `pnpm run quality`, 258/258 тестов, architecture, TypeScript, lint, web production build, Android web build и asset budget прошли.
- Новые исполняемые проверки: восстановление стартовой игры, загрузка модуля одновременно с анимацией, отмена и замена запросов, ошибка/повтор, unmount, недоступное хранилище, независимость ключей, повтор этапа, устаревший run ID, повреждённые/будущие снимки, отказ записи без ложного успеха; запуск настоящего `GameRuntime` подтверждает отсутствие вызовов прогрессии ТТТП в ТТТР и сохранение начислений в обычном бое.
- Локальный браузер: ТТТП → загрузочный переход → ТТТР; выбор ТТТР по умолчанию и перезагрузка; новый забег, пауза, возврат в меню с сохранённым счётчиком. Проверена узкая ширина меню без горизонтального переполнения. Для QA API направлен на локальный сервер без обработчиков; production-аккаунты не создавались.
- Свежие Android web сборки исходного commit и итогового кода в чистом каталоге публикации с одним и тем же установленным набором зависимостей: до — 1 173 817 bytes assets, 450 594 bytes JS, 325 397 bytes стартового статического JS-графа; после — 1 190 531 / 464 053 / 256 418 bytes соответственно. Общий assets вырос на 16 714 bytes, JS — на 13 459; стартовый статический граф уменьшился из-за динамической загрузки разделов. Эти числа не измеряют время до меню, FPS, CPU, память или батарею: для первого меню нужен и соответствующий отложенный раздел.
- Лимиты не менялись: 1 500 000 bytes assets / 340 000 bytes стартового JS. Зависимости и lockfile не менялись. Сохранились предупреждения Vite о `/game/...` URL и классификации маршрутов vinext.
- Native Android, SDK, toolchain, signing и release artifact не менялись; native release gate, установка на телефон и Google Play не выполнялись.

## Независимое ревью

Отдельный `independent_reviewer` с чистым контекстом нашёл одну P1-регрессию: первоначальный владелец коллекции размонтировался вместе с ТТТП, и поздняя рекламная награда могла записать старый снимок поверх обновлённого профиля после возврата. Исполняемый memory fixture подтвердил потерю нового имени и новый независимый барьер аккаунта при старом pending reward. Исправление: постоянный `GameSessionProvider` над обеими сценами. Регрессионный тест вызывает реальные коллекцию, барьер и local commit: переход в ТТТР и обратно сохраняет один gate, блокирует смену аккаунта до завершения attempt, сохраняет новое имя и начисляет награду один раз. Повторное независимое ревью подтвердило исправление; новых существенных замечаний нет. Ревьюер самостоятельно выполнил 26/26 тестов сессии, переключения, прогрессии и cloud lifecycle.

Публикация выполняется в существующий Site проекта; её фактический результат приводится в сообщении о завершении задачи. Этот отчёт описывает исходники и локальные проверки, не устанавливает статус rollout Android.
