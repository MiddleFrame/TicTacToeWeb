# Тесты Tic Tac Toe Plus

Запуск из корня проекта: `pnpm test` или `npm test`. Один и тот же runner работает на Windows и Linux: сам находит вложенные `*.test.mjs`, передаёт Node точные пути и возвращает его exit code. Файл теста за пределами известных групп вызывает ошибку, вместо незаметного пропуска. Пустая или неизвестная выбранная группа также вызывает ошибку.

| Группа | Команда | Что проверяет |
|---|---|---|
| domain | `pnpm run test:domain` | Правила боя, эффекты карт, цели, рогалик, валидация сетевого состояния и базовых входных данных |
| backend | `pnpm run test:backend` | SQL с настоящими миграциями в SQLite, rollback, ledger, квоты, receipts, миграция прогресса, HTTP-авторизация и входные данные |
| runtime | `pnpm run test:runtime` | Очередь, повтор и поздние ответы, смена аккаунта, реклама, Photon, загрузка миров, сохранения, отмена таймеров и анимаций |
| ui | `pnpm run test:ui` | Команды компонентов, доступность действий по состоянию, фильтры, lazy loading и отрисованный сервером контент |
| platform | `pnpm run test:platform` | Исполняемый WebView bootstrap, локальный fallback, форматы ресурсов и объявления Android-моста/упаковки |
| tooling | `pnpm run test:tooling` | Архитектурный анализатор на нарушающих границы фикстурах, измерение JS-графа, lint gate, SDK path и обнаружение тестов |

Можно выбрать сценарий: `node scripts/run-tests.mjs runtime --test-name-pattern="late or wrong-account"`. Для одного файла доступен обычный `node --test tests/runtime/progress-reliability.test.mjs`.

`pnpm run quality` включает все группы, проверку чувствительности тестов, архитектуру, TypeScript, lint и обе production-сборки с Android web budget. GitHub Actions использует ту же команду. Native unit/release-policy/artifact/lint проверки остаются в Gradle и запускаются по [инженерному протоколу](../docs/engineering-standards.md).

## Чувствительность к ошибкам

`pnpm run test:sensitivity` запускает семь выбранных сценариев на исправном коде, затем по одному вносит конкретные дефекты в одноразовую копию исходников:

- обход проверки администратора;
- покупки без проверки баланса или занятой транзакции;
- фильтр колоды, который всегда показывает все карты;
- повторное начисление награды за одну рекламу;
- подтверждение очереди ответом другого аккаунта;
- лишняя награда на границе SQL-квоты;
- Worker, который игнорирует отказ ограничителя API.

Каждый исходный сценарий обязан пройти. Его изменённый вариант обязан упасть именно внутри выбранного теста с ошибкой утверждения. Ошибка импорта, неизвестный тест или оставшийся зелёным дефект не засчитываются. Изменяются только копии `app`, `worker`, `tests`, `drizzle` и `package.json` во временном каталоге; рабочие исходники, `.wrangler`, Android/private и сервер не затрагиваются. Каталог удаляется после проверки. Это выборочная проверка качества тестов, а не процент покрытия всех возможных ошибок.

При намеренном изменении соответствующего правила нужно пересмотреть сценарий и его мутацию вместе. Если место мутации изменилось, gate останавливается с `Mutation anchor changed`: механически обновлять его без проверки поведения нельзя.

## Вспомогательные средства и ограничения

В `helpers/frontend-runtime.mjs` находится один загрузчик настоящего TS/TSX-модуля с явными подменами его внешних зависимостей, ручной hook harness, управляемые timers/RAF, deferred promise и memory storage. Неизвестный импорт вызывает ошибку. Тест должен оставлять настоящим код, ответственность которого проверяет, и подменять только его окружение или соседний порт. Harness требует явных render/commit, не моделирует React DOM, concurrent rendering или StrictMode и не доказывает поведение настоящего браузера.

`helpers/sqlite-d1.mjs` применяет настоящие миграции к отдельной in-memory SQLite, включает foreign keys и исполняет настоящий SQL. Batch выполняется в транзакции, конкурентные batch сериализованы, ошибка откатывает всю транзакцию и освобождает следующую. Это не эмуляция нескольких распределённых Worker-инстансов.

UI-тесты проверяют реальные обработчики и переданные дочерним компонентам данные; часть представлений рендерится настоящим React SSR. Они не измеряют CSS, положение элементов или прокрутку. Утверждать «кнопка видна» по наличию класса или `position: sticky` в файле запрещено. При изменении layout нужен отдельный браузерный проход: меню обоих миров, коллекция с раскрытыми колодами, конец пути, конец магазина, настройки, бой и итог забега. Проверить 320×568, 360×640 и короткий landscape; document не должен прокручиваться, а последние элементы специально выделенных списков должны быть достижимы. Android safe area и реальный WebView проверяются отдельно.

Текстовые проверки допустимы в `platform` только как проверки объявлений/упаковки. Они не доказывают работоспособность Keystore, рекламы, Credential Manager, аудио или native lifecycle. Для этих утверждений нужны исполняемые native/device сценарии. Настоящие Google, Photon и рекламные сети не вызываются unit-набором.

## Как добавлять тест

1. Выбрать конкретную ошибку и владельца поведения. До исправления сценарий должен воспроизводить её через реальную функцию, обработчик, SQL или компонент.
2. Использовать явные входные данные, управляемое время и отложенные ответы. В сценариях случайности задавать RNG либо проверять инвариант, который не зависит от случайного результата.
3. Проверять наблюдаемый результат: состояние, сохранённые данные, ответ, число вызовов или освобождение ресурсов. Не копировать алгоритм реализации в expected и не искать имя функции в исходнике.
4. Не добавлять второй тест того же сценария на том же уровне. Нормально проверять доменную политику и отдельно её подключение через HTTP или UI, когда каждый тест ловит свою ошибку.
5. При удалении проверки указать, чем важный риск уже покрыт либо почему прежняя проверка ничего не доказывала. Не уменьшать число тестов ради числа.

Исторические отчёты до 2026-10-19 содержат прежние плоские пути `tests/*.test.mjs`. Имена сохранённых файлов перенесены в соответствующие группы; прежний общий `game-engine.test.mjs` разделён на `domain/game-engine`, `card-effects`, `card-presentation`, `card-purchase`, `network-intents`, `roguelike`.
